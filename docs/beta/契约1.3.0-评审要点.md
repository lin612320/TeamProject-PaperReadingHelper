## 一、先说一个必须知道的冲突（已避开）

原计划 auth 错误码用 **4001 / 4002**。核对后发现：

```yaml
- { code: 4001, http: 500, name: STORAGE_ERROR, message: "文件存储失败" }   # 1.0.0 就已占用
```

**4001 被存储错误占了。** 所以本次 auth 段改用 **6001–6003**，与既有段完全不冲突：

| 码 | HTTP | 名称 | 文案 | 用途 |
|---|---|---|---|---|
| **6001** | 401 | `AUTH_INVALID_CREDENTIALS` | 用户名或密码不正确 | 登录失败；**账号不存在也用这条** |
| **6002** | 401 | `AUTH_TOKEN_INVALID` | 登录已失效，请重新登录 | 令牌过期 / 缺失 / 签名被篡改 |
| **6003** | 400 | `AUTH_USERNAME_TAKEN` | 该用户名已被占用 | 注册时用户名重复 |

现有码段排布：`1001–1004` 参数、`2001–2003` 文献、`3001–3003` AI、`4001` 存储、`5000` 内部 → **auth 顺位到 6 段**，后续留 `6004+` 给权限相关。

## 二、本次改了什么（四处）

### ① 新增 auth 四接口（#51）

| 接口 | 作用 | 鉴权 |
|---|---|---|
| `POST /api/auth/register` | 注册，用户名唯一，bcrypt 入库，直接签发令牌 | 否 |
| `POST /api/auth/login` | 登录，签发 JWT | 否 |
| `GET /api/auth/me` | 取当前用户（前端启动时判断登录态，避免刷新闪登录页） | 是 |
| `POST /api/auth/logout` | 登出；无状态 JWT 下服务端只记日志，前端清本地令牌 | 是 |

新增 `components.securitySchemes.bearerAuth`（`Authorization: Bearer <token>`）。
新增模型：`AuthRegisterRequest`、`AuthLoginRequest`、`AuthToken`、`UserInfo` 及两个 ApiResponse 包装。

**四条硬约束**（写进 `x-conventions.auth.invariants`）：

1. 密码只在传输中出现一次，**不落库、不写日志、不回显**
2. 账号不存在与密码错误返回**同一个 6001**（防止探测用户名）
3. 令牌过期 / 篡改 → 6002 + 401，前端据此清令牌跳登录
4. 除注册/登录外，**其余接口全部要令牌**

### ② 阅读顺序字段（#52）

- `Citation` 新增 `readingOrder`（可空，页内从 0 起）
- `chunks.reading_order`（INT，可空）写进 `x-conventions.reading_order`，含语义与 DDL
- **关键约定**：历史数据为 null，**前端不得依赖它定位**，定位仍看 `page + bbox`
- 语义：按 `(band, column, y0, x0)` 排；跨栏块 `column=-1` 排本带末尾

### ③ 越权口径定死（#53）

```yaml
x-conventions.authz:
  strategy: 越权一律按「资源不存在」处理，不返回 403
  code: 2001
  http: 404
```

覆盖 6 处：文献详情 / 删除 / 取文件 / 问答 / 划词解释 / 导入。
**理由**：返回 403 等于告诉攻击者「这个 id 存在，只是不是你的」，可用来枚举他人文献。
**铁律**：越权响应不得携带他人任何业务字段，连标题都不许回显。

### ④ 划词拦截规则（#53，给 #67 当前置）

```yaml
x-conventions.explain_guard:
  空 / 长度 < 2 / 全是数字（含数字与标点） → 前端不弹浮层、不发请求
```

## 七、增补 · 1.3.1（2026-11-20，P1 拍板）

### 起因：`bboxMode` 语义与需求卡自相矛盾（BUG-023）

同一份文档体系里出现了两条互斥的验收：

| 位置 | 原文 | 推出 |
|---|---|---|
| 契约 1.3.0 `bboxMode` 描述 | 按**版面类型**分：双栏页 = `block` | 双栏**永远不可能** `precise` |
| 需求卡 B01 验收第 4 条 | 「双栏页仍为 `block`，不得冒充 `precise`」 | 同上 |
| 需求卡 B03 验收第 1 条 | 「双栏论文 10 题：`bboxMode=precise` 命中 ≥7」 | 双栏**必须**能 `precise` |

B03 这条在 1.3.0 口径下是**不可达**的——按契约实现，命中率恒为 0。这不是老实现在 bug，是契约写错了维度。

### 改法：从「版面类型」改成「框精度」

```yaml
bboxMode:
  precise: 框覆盖目标段落，且不跨栏（单栏、双栏同样适用）
  block:   框是段落内多块并集 / 跨栏
  null:    无边线信息
```

**必须遵守！** 判据只看两件事：① 是否跨栏 ② 是否覆盖目标段落。单栏 / 双栏不再直接决定取值。

### 连带影响（已同步）

1. `01-api-contract.yaml` → `1.3.1-frozen`，`frozen_at_1_3_1: 2026-11-20`，changelog 追加一节
2. `Beta需求卡.md` B01 验收第 4 条 → 改为精度口径；B03 验收不变（现在是可达的）
3. `docs/测试/BugList.md` → 新增 BUG-023 记录本次矛盾
4. 前端**不改**：本来就只按三态切样式，不解析「单栏/双栏」
5. Alpha 的「65/65 全 `block`」按 1.3.1 口径复核为**合规**（旧口径下的正确行为），不算缺陷，不进 BugList 的 Bug 区

### 给 Beta 的一句话

> B01 只重排顺序，不承诺提精度；B03 才是提精度的卡。B01 交出来 `block` 不算未完成，B03 交不出来 `precise ≥7` 才算。
