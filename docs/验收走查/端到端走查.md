## 一、开始前的准备（3 分钟）

### 1. 起依赖

```bash
docker compose up -d          # 只起 postgres + redis
docker compose ps             # 两个都必须是 healthy
```

### 2. 起三个服务（顺序不能乱）

| 顺序 | 服务 | 命令 | 就绪信号 |
|---|---|---|---|
| 1 | ai-service | `cd ai-service && uvicorn app.main:app --port 8000` | `curl localhost:8000/internal/health` 返回 `dbReady: true` |
| 2 | backend | `cd backend && mvn spring-boot:run` | 日志出现 `Started BackendApplication`，端口 8080 |
| 3 | frontend | `cd frontend && npm run dev` | 浏览器能开首页 |

> ⚠️ AI 服务没就绪就测上传，会得到 `parse_status=failed`，那不是后端的错。

### 3. 测试数据（四份，缺一不可）

| 文件 | 用途 | 哪一步 |
|---|---|---|
| `demo-10p.pdf`（10 页真论文） | 主链样本 | ②③④⑤ |
| `big-20p.pdf`（20 页真实论文） | 滚动流畅度 | ③ |
| `fake.pdf`（其实是 docx，只是改了后缀） | 骗后缀 | ⑥ |
| `not-a-pdf.docx`、`empty.pdf`、`>50MB.pdf` | 边界报错 | ⑥ 补充 |

## 二、六步走查（照着做，每步都有判据）

### 步骤 ① 一条命令起全栈 —— 对应 **F4**

| 项 | 内容 |
|---|---|
| 操作 | `docker compose down` → `docker compose up -d` → 打开演示地址 |
| ✅ 通过 | 一条命令起全栈，不需要手动补步骤；`docker compose ps` 里数据库与缓存都 healthy；8080 与前端页面都能访问 |
| ⚠️ 保留 | 一条命令能起 **依赖**，但三个应用服务要手动开 |
| ❌ 断 | 起不来 / 需要额外手改配置 / 有服务启动失败 |
| 现状（11-03） | ❌ 三份 Dockerfile 还没写（`#23`），只能手动起 → 记为「⚠️ 保留」，不判死 |

**断点记录**：断在哪一步 → 谁负责 → 什么时候修。

---

### 步骤 ② 上传一篇 PDF —— 对应 **F1**

| 项 | 内容 |
|---|---|
| 操作 | 点「上传」选 `demo-10p.pdf` → 确认 → 计时到列表出现 |
| ✅ 通过 | 列表出现该文献；标题、上传时间正确；`source=upload`；**从点确定到列表出现 < 3 秒** |
| ⚠️ 保留 | 出现但慢于 3 秒；或要刷新页面才看到 |
| ❌ 断 | 列表不出现 / 报错 / 页面崩 / 无上传入口 |
| 细化判据 | 接口层实测口径见冒烟 F1-01；页数不在此判（见步骤 ②-补） |

**②-补（页数真实性，对应 F1-10 / BUG-006）**

| 项 | 内容 |
|---|---|
| 操作 | 上传后轮询详情，`parseStatus` 变 `ready` 后再看列表 |
| ✅ 通过 | 页数 = **10**（与文件一致）；`parseStatus=ready`；`chunkCount > 0` |
| ❌ 断 | 页数恒为 15、`chunkCount` 恒为 128（假数据）；或 `parseStatus=failed` |
| 现状（11-03） | mock 已默认关闭，但解析超时 25 秒（契约 10~60 秒）→ 大概率 `failed`，**先记为 ❌，等 `#13` 调完再复测** |

---

### 步骤 ③ 打开、翻页、缩放 —— 对应 **F2**

| 项 | 内容 |
|---|---|
| 操作 | 列表点开 → 看第 1 页 → 跳页输入 `3` → 缩放 50% / 200% → 从头滚到底（用 `big-20p.pdf`） |
| ✅ 通过 | ① 第 1 页完整显示，对照原文件无错位、无空白、无重叠 ② 跳页输入 `3` 后页码与内容一致 ③ 缩放 50%/200% 文字不串行，200% 可横向滚动 ④ 20 页连续滚动无整页空白、无卡死 |
| ⚠️ 保留 | 能用但偶发白屏 / 缩放后位置跳回顶部 |
| ❌ 断 | 打不开 / 白屏 / 渲染错位 / 跳页不准 |
| 边界补充 | 跳页输入 `0`、`999` 应自动纠正到第 1 页 / 末页，不报错（F2-06） |

---

### 步骤 ④ 提问，拿答案 + 页码 —— 对应 **F3（核心）**

| 项 | 内容 |
|---|---|
| 操作 | 侧栏问：「这篇文章提出的方法核心是什么？」 |
| ✅ 通过 | ① **20 秒内**返回 ② 答案与论文内容相关、不编造 ③ 附 ≥1 条引用，含**页码（从 1 起）**和原文片段 ④ `code=0` |
| ⚠️ 保留 | 有答案但超过 20 秒；或引用只有片段没页码 |
| ❌ 断 | 报错 / 空回答 / 超时 / 答案与论文无关 |
| 现状（11-03） | ❌ **必断**：`ai-service` 没有 `/internal/qa/ask`，前端会提示「AI 服务异常」（`3001`） |

**④-补（防编造，对应 F3-05）**

问一个论文里没有的事（如「用了多少只小白鼠」）→ ✅ 要求**逐字**返回「本文未涉及该内容」，且 `citations` 为空数组。返回任何数字、实验、文献都判 ❌。

**④-补（错误分支）**

| 场景 | ✅ 判据 |
|---|---|
| 空问题 / 纯空格 | 前端拦截或返回 `2003` |
| `paperId=99999` 提问 | 提示「文献不存在」，`2001` / 404 |
| 解析中提问 | 提示「解析中，请稍候」，`2002` / 409，不无限转圈 |
| 停掉 ai-service 再问 | 中文提示失败，不白屏，`3001` 或 `3002` |

---

### 步骤 ⑤ 点引用页码，PDF 跳回原文 —— 对应 **F3**

| 项 | 内容 |
|---|---|
| 操作 | 点第 ④ 步返回的引用页码 |
| ✅ 通过 | PDF 跳到该页，显示页码与引用一致，引用片段能在页面上找到（空格换行差异可忽略） |
| ⚠️ 保留 | 能跳但差 1 页 |
| ❌ 断 | 点了没反应 / 跳到错误页 |
| 现状（11-03） | ❌ 依赖 ④，且页码点击联动（`#8`）还没做 |

---

### 步骤 ⑥ 故意传错文件，看报错 —— 对应 **F4**

| 项 | 内容 |
|---|---|
| 操作 | 依次传 `not-a-pdf.docx`、`fake.pdf`、`empty.pdf`、`>50MB.pdf` |
| ✅ 通过 | ① 界面上有**中文红字**提示，不是英文报错、不是白屏 ② 列表不新增脏数据 ③ 三份错误响应结构统一（有 `code` 和 `message`，`data` 为 null） |
| ❌ 断 | 报错是英文/堆栈、页面崩、脏数据入库 |
| 具体码 | 非 PDF → `1002`；伪装 PDF → `1002`；空文件 → `1001`；超 50MB → `1003` |

## 四、断点登记规则（断了以后怎么处理）

每发现一个断点，**当场**做三件事：

1. **记一行**：步骤、现象、复现命令、谁负责、期限（下表格式）
2. **开 Issue**：标题写现象不写评价（对：「上传 51MB PDF 返回 5000」，错：「P4 上传写得不行」）
3. **在站会报**：一句话——走到第几步、断在哪、催了谁
