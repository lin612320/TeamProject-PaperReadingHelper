## 三、新发现：BUG-004 回归（今日最重要）

| 项 | 内容 |
|---|---|
| 现象 | 纯文本文件（1,900 字节，文件头是 `This`）改成 `.pdf` 后缀上传，**HTTP 200，入库 `id=10`** |
| 复现 | `curl -F "file=@data/e2e/fake.pdf" /api/papers` → 200 |
| 根因 | `410ed69` 为了修 BUG-009（`.docx` 后缀的真 PDF 被拒/被收），在 `upload()` 里加了后缀校验，**同时删掉了 `isPdf(file)` 的调用**。`isPdf()` 方法还在 `PaperController.java:195`，但**全后端无任何调用点**，成了死代码 |
| 影响 | 这正是 BUG-004 当初修掉的问题（按后缀判断 → 伪装文件入库）。`BugList` 里 BUG-004 标着「已修复」，实际已回归 |
| 冒烟影响 | F1-04（伪装 PDF 应被拒）表里标"通过"，那是**改动前**测的，现在会失败 |
| 修法 | 两个校验都留：先查后缀快速拒绝，再用文件头兜底防伪装 |

```java
if (originalName == null || !originalName.toLowerCase().endsWith(".pdf")) {
    throw new BizException(ErrorCode.FILE_NOT_PDF);   // 快速拒绝
}
if (!isPdf(file)) {                                    // 内容兜底
    throw new BizException(ErrorCode.FILE_NOT_PDF);
}
```

> 备注：`.docx` 后缀（内容是 PDF）现在返回 `400/1002` ✅，说明后缀校验生效；坏的是「后缀对、内容假」这一半。
