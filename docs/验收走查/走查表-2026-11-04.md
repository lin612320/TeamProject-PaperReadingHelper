## 二、逐条证据

### ① 起依赖（✅ healthy）与全栈（⚠️ 未验证）

```
papermind-postgres	Up (healthy)
papermind-redis	    Up (healthy)
```

全栈 `docker compose up -d --build` 未执行：ai-service 镜像要装 torch（2GB+），校园网拉取耗时不可控。步骤① 的判据「一条命令起全栈、ps 全 healthy」本轮无法判定。

### ② 上传 PDF —— ✅ 通过

```
POST /api/papers  (demo-7p.pdf, 1,234,254 字节 / 7 页)
HTTP 200   总耗时 0.380314s

{"code":0,"data":{"id":5,"title":"demo-7p","filename":"demo-7p.pdf",
 "pageCount":0,"chunkCount":0,"parseStatus":"pending","parseError":null,
 "source":"upload","fileSize":1234254,"createdAt":"2026-11-04T19:45:11"}}
```

0.38 秒 < 3 秒判据 ✅；字段与契约 `PaperDetail` 一致、**无 `path`** ✅；状态 `pending` 正确 ✅。

### ②-补 解析与页数 —— ❌ 断

```
GET /api/papers/5
{"parseStatus":"failed","pageCount":0,"chunkCount":0,"parseError":"unknown error"}
```

- **根因**：AI 服务（8000 端口）没启动，解析必然失败 —— 环境问题，不算代码缺陷。
- **代码缺陷**：`parseError` 只写了 `unknown error`。真实是「连接被拒绝」，但 `ConnectException.getMessage()` 为 null，`ParseService` 兜底成了这三个字，无法定位（BUG-008）。

### ③ 渲染 / 翻页 / 缩放 —— ✅ 真机通过

| 层 | 结果 |
|---|---|
| 数据层 | ✅ `GET /api/papers/5/file` → 200，1,234,254 字节，头 `%PDF`，与源文件逐字节等长 |
| 渲染层 | ✅ **真实浏览器打开 `/reader/5` 渲染正常** |
| 翻页/缩放/跳页 | ⏳ 待补确认（走查时用无头浏览器，交互无法验证） |

> **一处更正**：本轮最初用无头浏览器截图时页面卡在「正在加载文档…」，据此曾记为缺陷。经真机复核，**渲染是正常的**，那是无头环境对 pdf.js worker 的限制所致，不是代码问题。原 BUG-010 撤回。
>
> 附带事实（不影响当前功能，留作 Beta 参考）：后端对 `/api/papers/{id}/file` **不支持 Range 请求**（带 `Range` 头仍返回 200 全量、无 `Accept-Ranges`/`Content-Range`）。文件小的时候没影响，论文多大几十 MB 时首屏会变慢，届时再加分块返回。

### ④ 提问 —— ⚠️ 错误分支通过，正例未测

提问接口实测（`paperId=5`，解析失败状态）：

| 场景 | 请求 | 实际响应 | 判定 |
|---|---|---|---|
| 未解析就提问 | `{"paperId":5,"question":"这篇文章提出的方法核心是什么？"}` | `409 {"code":2002,"message":"文献尚未解析完成，暂时无法提问"}` | ✅ 与真机看到的「文件未解析」一致 |
| 空问题 | `question: "   "` | `422 {"code":2003,"message":"问题不能为空"}` | ✅ |
| 不存在文献 | `paperId: 99999` | `404 {"code":2001,"message":"文献不存在"}` | ✅ |

**正例（拿到答案 + 页码）未测**：需要 AI 服务 + `DEEPSEEK_API_KEY`。

> 测试小技巧：在 PowerShell 里用内联字符串传中文 JSON 会因编码变成乱码、被判 `1001`；要写成 UTF-8（无 BOM）文件再 `--data-binary "@file"`。这一条差点被我记成缺陷，实际是测法问题。
