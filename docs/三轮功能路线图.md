# 论文阅读助手 · 三轮迭代功能路线图

> 团队：七仙过海 · 7 人 · 一学期三轮迭代（Alpha / Beta / RC）
> 核心原则：**每一轮都有主菜，每一轮都留活给下一轮。**

---

## 一、三轮任务池

| 能力 | Alpha（W5–W7，2.5 周） | Beta（W8–W11） | RC（W12–W15） |
|---|---|---|---|
| PDF 渲染 | PDF.js **单栏连续渲染** + 翻页/缩放 | **双栏阅读流** + 高保真滚动 | 批注/书签 + 批注-原文双向跳转 |
| 问答 | 抽文本 → 检索 → 答 + **引用页码** | 引用句 **bbox 定位 + 高亮跳转** | 重排/缓存/成本控制 |
| 外部检索（F5） | 只预埋字段与契约 | **F5-a：关键词 → arXiv + OpenAlex → 导入 → 进问答主链** | **F5-b：多源聚合去重 + 排序 + 检索历史** |
| 用户 | 硬编码单用户，无鉴权 | 登录 + 多用户数据隔离 | 权限/限流 |
| 对比 | ❌ 不做 | ❌ 不做 | ✅ 2–4 篇 Markdown 对比表 |
| 行为看板 | ❌ 不做（只建空表） | ❌ 不做 | ✅ 时长/词云/雷达图 |
| 部署 | 本机 `docker compose up` | CI 自动构建 + 数据备份 | 一键部署包 + 压测 + 演示视频 |

### 为什么必须这样留白

- ✅ 正确做法：Alpha 建表时把 `bbox`、`reading_session`、`annotation`、`source/doi` **先留好**，后续只填不改表
- ❌ 错误做法：Alpha 把 bbox 高亮做完 → Beta 无核心技术点，只能吹牛

## 二、三轮出口条件（逐轮抬升，对应 PPT 第 12 页）

| 轮次 | 出口条件 |
|---|---|
| **Alpha** | 上传后能提问，返回答案 + 引用页码；点击页码跳转对应页；页面不崩 |
| **Beta** | 双栏阅读 + 点击引用跳回原文并高亮 + 登录多用户 + 关键词检索导入可用 |
| **RC** | 阅读周报看板可用 + 无 P0/P1 + 一键部署可交付 |

三篇出口条件一次比一次高，PPT 要求的「出口条件动态调整」才有真实叙事。

## 三、Alpha 2.5 周节奏（不要排 4 周）

| 时间 | 目标 | 硬卡点 |
|---|---|---|
| **D1–D3** | 契约冻结 + 空壳能起 + Issue 到人 | 无人可开工即视为失败，P1 负责 |

| **D13–D15** | 冒烟测试、Bug List、两篇博客、出口条件定稿 | 出口条件 = 主链不断、无 P0 |

## 四、七人分工明细

| 编号 | 角色 | Alpha 只做这些 | Alpha 交付物 | Beta / RC 接力（保证有活干） |
|---|---|---|---|---|
| **P1 林子航** | 组长·架构·集成 | API 契约、Compose 骨架、评审、燃尽图、例会 | `api-contract.yaml` + 可启动空壳 | Beta：接口版本演进；RC：发布与演示 |
| **P2** | 前端·PDF 核心 | PDF.js 单栏渲染 + 翻页缩放 + 页码跳页 + **0.5 天 bbox 坐标预研（只出结论）** | 能渲染、能翻页、能滚到指定页 | Beta：双栏流 + 高亮层；RC：批注书签 |
| **P3** | 前端·页面 | 上传页、文献列表、问答侧栏（含 loading/错误态） | 三个页面点得通 | Beta：登录态 + 检索页；RC：ECharts 看板 |
| **P4** | 后端·业务 | 上传、文献 CRUD、转发问答三组接口（单用户）+ 契约预留 `/api/search` | Postman 全绿 | Beta：**F5-a 检索适配层（arXiv + OpenAlex）**；RC：对比接口 |
| **P5** | AI·RAG | PyMuPDF 抽文本（双栏**先按 blocks 顺序凑合**）、切片、pgvector 检索、答 + **页码** | 问答接口返回答案 + 页码 | Beta：双栏排序 + bbox 定位（主菜）；RC：跨文献对比 Prompt |
| **P6** | 数据·部署 | 建库建表（含预留可空字段与空表）、Redis、Compose、日志 | 一键起全栈 | Beta：检索缓存 + 索引优化 + CI；RC：压测 + 发布包 |
| **P7** | 测试·文档 | 冒烟用例、Issue 板、**第 6/7 周两篇 Scrum 博客** | Blog ×2 + 用例表 | Beta：场景测试 + 检索降级用例；RC：出口条件 + 测试报告 + 视频 |

### 分工红线

- **P2 的引用跳转是全项目最难点** → D2–D3 就出 demo，不行就降级为「跳页 + 段落高亮」
- **P5 的 bbox 坐标系**（相对页面宽高 vs PDF 用户单位）必须与 P2 在 D3 前对齐
- **P5 在 Beta 已扛双栏 + bbox，不要再给他检索**；检索归 P4
- **P7 一人扛测试 + 文档** → 例会照片、签入记录当场收，不要周末补

## 五、F5 关键词检索归属

| 迭代 | 范围 |
|---|---|
| Alpha | 不实现。只留 `papers.source/doi/arxiv_id/external_url` 字段 + `/api/search` 契约占位 |
| Beta | **F5-a**：关键词 → arXiv API + OpenAlex → 结果卡片 → 一键导入 → 直接进问答主链 |
| RC | **F5-b**：多源聚合去重（DOI → arXivId → title+year）、相关性排序、检索历史、勾选 2–4 篇接对比表 |

### 「权威网站」必须落到具体 API

| 源 | 接口 | 需要 key | 能拿到 |
|---|---|---|---|
| arXiv | `export.arxiv.org/api/query` | 否 | 元数据 + OA 全文 PDF |
| OpenAlex | `api.openalex.org/works` | 否 | 大而全元数据、DOI、OA 链接 |
| Semantic Scholar | `api.semanticscholar.org/graph/v1` | 免费 key | 元数据 + 摘要 + 引用关系 |
| Crossref | `api.crossref.org/works` | 否 | DOI 权威元数据 |
| PubMed / PMC | NCBI Entrez API | 免费 | 生医方向 |

- ❌ 不要写「在权威学术网站上检索论文」——不可测试
- ❌ 不要碰：知网、万方（无公开 API）、IEEE Xplore / Web of Science / Scopus（需机构订阅）
- ⛔ 合规红线：**只抓开放获取（OA）全文，非 OA 只给原文链接，绝不绕过付费墙**
