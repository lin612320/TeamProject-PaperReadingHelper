# 论文阅读助手 · Alpha 阶段预期功能清单

> 团队：七仙过海 · 项目：论文阅读助手（PaperMind / ChunxiaoPaper）
> Alpha 周期：2.5 周（D1–D15，对应第 5–7 周）
> 一句话定位：**Alpha = 一条能跑通的最薄主链**，不是"功能堆完"。

---

## 一、Alpha 交付的 4 个功能（F1–F4）

判断标准：能在**一台笔记本**上从头到尾走一遍，中途不报错。每个功能一个可验收标准。

| 编号 | 功能 | 输入 → 输出 | 验收标准（可测） | 负责人 |
|---|---|---|---|---|
| **F1** | 文献上传与列表 | 上传 PDF → 存磁盘 + 记录元数据（标题/页数/上传时间）→ 列表可见 | ① 10 页 PDF 上传 < 3s ② 非 PDF 有明确报错 ③ 刷新后列表仍在 | P4 + P3 |
| **F2** | PDF 在线阅读 | 点列表 → PDF.js 渲染 → 翻页、缩放、跳指定页 | ① 渲染无白屏/无错位 ② 页码跳转生效 ③ 20 页文档滚动流畅 | P2 |
| **F3** | 单篇精读问答（核心） | 输入问题 → 检索本文相关段落 → 返回**答案 + 引用原文片段 + 页码** | ① 答案与论文内容相关、不编造 ② 引用页码准确率 ≥ 70%（抽 10 题人工核对）③ 点击页码 → PDF 跳到对应页 ④ 单次响应 < 20s | P5 + P3 + P2 |
| **F4** | 基础工程化 | `docker compose up` → 全栈可访问；失败有提示 | ① 一条命令起全栈 ② 前后端异常有友好提示不白屏 ③ 有运行日志 | P6 + P1 |

### 验收标准写法对照

- ✅ 正确示例：「抽 10 题，≥ 7 题引用页码正确」——可证、可测
- ❌ 错误示例：「实现智能问答功能」——**无法测试的需求**（见需求分析 PPT 第 43 页）

## 四、Alpha 演示脚本（60 秒，照着走一遍就是验收）

1. `docker compose up` → 打开 `localhost:8080`（F4）
2. 上传一篇双栏英文论文 PDF → 列表出现（F1）
3. 点开 → PDF 渲染，翻到第 3 页（F2）
4. 侧栏提问：「这篇文章提出的方法核心是什么？」→ 返回答案 + 引用片段 + 页码（F3）
5. 点引用页码 → PDF 跳到该页（F3）
6. 故意传一个 `.docx` → 出现红字报错（F4）

**任何一步断，Alpha 不算过。**

## 五、Alpha 出口条件（写进测试报告）

> 上传 PDF 后可在浏览器内阅读，并针对该论文提问获得带引用页码的答案，点击页码可跳转对应页；全流程无 P0 崩溃，一键启动可用。

---

## 六、F5（关键词检索）在 Alpha 的边界

- **不实现检索功能本身**，只做两件事：
  1. `papers` 表加 `source / doi / arxiv_id / external_url` 字段（P6）
  2. 契约预留 `/api/search` 与 `PaperMeta` 模型（P4）
- 目标：Beta 开工第一天就能直接写适配器，不返工、不改表。

---

## 七、Alpha 三条禁令（防过度开发）

1. 不碰 bbox 高亮、双栏排序、批注、看板、检索——**一律进 Beta/RC 任务池**。
2. 不做鉴权、不做多用户、不做文件并发——**单用户跑通即算过**。
3. 新需求进 Backlog，**不插进本轮 Sprint**。
