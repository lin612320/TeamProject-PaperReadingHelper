## 四、越界红线（被 review 打回最多的情况）

| 谁 | 不要碰 | 原因 |
|---|---|---|
| P2 | `backend/`、契约文件 | 渲染与接口分离，改契约会让全组返工 |
| P3 | PDF 渲染核心逻辑 | 与 P2 冲突，同一文件两人改必冲突 |

| P6 | 业务代码 | 只动数据库与部署 |
| P7 | 顺手改代码「修一下」 | 测试只提 Issue，改代码不由你负责 |
| 全员 | 新增未列入 Issue 的功能 | 违反「新需求进 Backlog」禁令 |

## 五、接口对接人（跨模块沟通指定这一个）

| 事项 | 找谁 |
|---|---|
| 契约字段、接口增删 | **P1** |
| bbox 坐标系、页码语义 | **P2 ↔ P5**（D3 前必须对齐） |
| 前端调后端报错 | **P3 ↔ P4** |
| 表结构、字段缺失 | **P6 ↔ P4 / P5** |
| PDF 文件取不到 / 渲染异常 | **P2 ↔ P4** |

**规则**：跨模块问题走对接人，不在群里圈所有人。**卡住 2 小时立刻上报 P1，不许自己憋着。**

## 六、每日纪律

1. 例会前必须 `git push`，否则视为当日任务未完成
2. commit 必须带 Issue 编号：`feat: PDF.js 单栏渲染接入 (#5)`
3. Issue 状态当天更新（`待开始 / 进行中 / 待评审 / 已完成`）
4. 分支：日常推 `master`；`release` 任何人不得推送
5. 例会 10 分钟：昨天做了什么 / 今天做什么 / 卡在哪
