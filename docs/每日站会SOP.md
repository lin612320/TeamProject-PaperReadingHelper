# 每日站会（Daily Scrum）执行规范

> 依据：与都老师 2026-10-21/22 的沟通结论 + 需求分析 PPT 第 3 页「Scrum Meeting」要求
> 责任人：P1（主持与节奏）· P7（记录与留证）
> 适用范围：Alpha 全程 D1–D15（**D1 = 2026-10-27 周二，首次站会**，详见 [例会时间安排.md](例会时间安排.md)）

---

## 一、老师给的四条硬边界（不可突破）

| # | 结论 | 原话要点 |
|---|---|---|
| 1 | **线上可以，有条件线下最好** | 线下不易组织时用线上，不是禁止线下 |
| 2 | **必须高频，频率低了不行** | 「每日例会可以有弹性，但原则上需要保证高频」 |
| 3 | **群里文字汇报不行** | 「就是在群里汇报工作」→ 老师明确回答「**这个不行**」 |
| 4 | **时长很短，协调不难** | 「最多十五分钟，协调起来并不难」 |

**推出来的三条红线**：

- ❌ 用微信群/QQ 群发「昨天做了X，今天做Y」代替会议 —— **老师已否决**
- ❌ 一周只开一两次 —— 频率不达标，视为未执行 Scrum
- ❌ 一次开半小时以上 —— 时长失控，说明开成了评审会

> ✅ 关键认知：**弹性 ≠ 低频**。弹性指的是「哪天谁确实有事可以线上补、可以调时间」，不是「今天不想开就不开」。

## 二、形式与工具

| 项 | 首选 | 备选 | 禁止 |
|---|---|---|---|
| 形式 | **线下碰面**（教室/图书馆/宿舍楼下） | 线上语音会议 | 群消息文字汇报 |
| 线上工具 | 腾讯会议 / 飞书会议（开麦即可，不必强求视频） | 微信语音通话（≤7人可用） | 只发文字 |
| 时长 | **10–15 分钟**，站姿或半站姿 | — | 超过 20 分钟 |
| 固定时间 | **每天 20:30–20:45**（已按 P1 课表核对，晚间无课） | 21:20–21:35 / 19:30–19:45 | 时间天天变 |

> 时间**固定下来写进群公告**。天天改时间＝有人会漏，漏两次就开始散。
> 排期依据见 [`例会时间安排.md`](例会时间安排.md)。

## 三、频率：弹性怎么弹

| 情形 | 做法 |
|---|---|
| 周二 ~ 周日 | **每天开**（周一休会，见下） |
| 周六 / 周日 | 照常开，**时间可调整**（提前/推后 30 分钟，或两天合并成周日一次），但不得整周不开 |
| 考试/课程冲突当天 | 改到当晚 22:30 或次日早 8:00 **补开**，不取消 |
| 有人请假 | 会议照开，缺席者会后看记录并在群里补一句「已阅 + 我的今日任务」 |
| 连续 2 天不开 | ⛔ 视为频率不达标，由 P1 在例会说明并在博客里如实写 |

**出席红线**：到会少于 5/7 人 → 改时间重开，不记为有效站会。

### 三条灵活规则（定稿）

| 规则 | 说明 |
|---|---|
| **周一休会** | 周一白天课最重（人工智能II + 大学物理II + 单双周课），晚上不排站会。**燃尽图照记**（P7 跑一次脚本，10 秒） |
| **不强制每人每天关一条 Issue** | Issue 本身是 2~4 天的活，一天关一条不是标准。站会只问"推到哪一步了"，只有真正做完才关 Issue |
| **周末可调时间** | 周六/周日站会允许提前或推后 30 分钟，也允许两天合并成周日一次；但不得整周只开两三次 |

**频率下限：每周至少 6 次站会**（周一休会日除外）。低于这个数就是频率不达标。

## 四、15 分钟流程（分钟级）

| 时间 | 环节 | 谁 | 要点 |
|---|---|---|---|
| 0–1′ | 开场点名 | P1 | 报今天日期、剩余 Issue 数（燃尽图数值） |
| 1–8′ | 三人问逐人过 | 全员，每人 ≤60 秒 | 见下方模板，**只说事实不说方案** |
| 8–11′ | 障碍处理 | P1 | 只做「谁来解决 + 何时给结果」，不在会上解决 |
| 11–13′ | 今日分工确认 | P1 | 对照 `docs/Alpha_Issue清单.md` 确认今天各自认领哪条 |
| 13–15′ | 记录与留证 | P7 | 截屏/拍照 + 填记录 + 跑燃尽图脚本 |

**发言纪律**：

- 技术争论超过 2 分钟 → 「这个问题会后 P2 和 P5 单独拉 10 分钟」，记进「会后议题」
- 不许在会上演示代码、不许开屏幕共享看代码（那是评审会）
- 不许在会上重新讨论已定的分工（改分工走会后 + 更新文档）

## 五、每人 60 秒说三件事（照着念）

```text
1. 昨天推到哪一步：#5 PDF.js 单栏渲染，做到「翻页按钮能点」（commit 5e49d6d）
   —— Issue 还没关也照实说，不要为了凑数硬关
2. 今天推到哪一步：#6 把缩放做完，预计 18:00 前推
3. 我卡在：缺双栏样本 —— 找 P7 要
```

**说明**：一条 Issue 通常是 2~4 天的活，所以「昨天完成了什么」允许是**进度**而不是「已关闭」。
只有真正做完、能演示了才点 Close —— 提前关 Issue 会让燃尽图失真。

- ✅ 带 Issue 编号 + commit 号，能和签入记录对上
- ❌ 「差不多做完了」「还在弄」——无法核对，等于没说
- 阻塞必须说，藏着到截止日才爆是团队最大风险

## 六、记录与留证（直接对应作业四要素）

PPT 要求 Scrum Meeting 博客必须有四样东西，站会就是采集现场：

| 作业要求 | 站会当天怎么采 |
|---|---|
| ① 每人工作 + Issue 内容与链接 | P7 记录每人三问，Issue 号直接引用 `Alpha_Issue清单.md` |
| ② 燃尽图 | 会后 P7 跑一次脚本：`.\scripts\burndown.ps1 -Remaining <N>` |
| ③ 例会照片 | 线下拍照；**线上则截屏参会人列表画面**（可作照片证据） |
| ④ 每人代码/文档签入记录 | 会后 `git log --author=<名字> --since=昨天` 截图归档 |

**留证要求**：截图里要能看清**日期、参会人、会议界面**。只截自己头像不算。

## 七、例会记录模板（P7 每天照抄一份）

文件命名：`docs/例会记录/D<n>-YYYY-MM-DD.md`

```markdown
# 第 n 天站会记录（YYYY-MM-DD 20:30）

- 形式：线下（图书馆 3F）／线上（腾讯会议）
- 出席：P1 P2 P3 P4 P5 P6 P7（7/7）；缺席：无
- 剩余 Issue：24 / 28（理想 22，落后 2 条）

## 每人三问
| 成员 | 昨天完成（Issue） | 今天计划（Issue） | 阻塞 |
|---|---|---|---|
| P1 | #1 契约冻结 | #2 Compose 骨架 | 无 |
| P2 | #5 单栏渲染（5e49d6d） | #6 翻页缩放 | 缺双栏样本 |

## 障碍与决策
- 障碍：PDF 双栏样本缺失 → 责任人 P7，今日 12:00 前提供
- 决策：本日不新增功能，专注 F2

## 会后议题（不占站会时间）
- P2 ↔ P5：bbox 坐标系对齐，今日 20:00 单独 10 分钟

## 留证
- 照片/截屏：`docs/例会记录/附件/D<n>-meeting.png`
- 签入记录：`docs/例会记录/附件/D<n>-commits.png`
```

## 八、常见反模式（对号入座自查）

| ❌ 反模式 | 症状 | 后果 |
|---|---|---|
| 群内文字汇报代替会议 | 「我们在群里说了」 | 老师已明确否决，作业不认 |
| 开成汇报大会 | 一人讲 5 分钟，领导式训话 | 超时、没人愿意开 |
| 开成技术讨论会 | 两个人争论 15 分钟 | 其他人全程插不上话 |
| 开成问责会 | 「你为什么没做完」 | 成员开始隐瞒问题 |
| 只报进度不报阻塞 | 到截止日集体爆雷 | 燃尽图最后一天断崖 |
| 不记录不留证 | 博客里没有照片和签入记录 | 作业直接扣分 |
| 时间天天变 | 有人总缺席 | 频率实质下降 |

## 九、给老师的可验证痕迹（应对「频率是否达标」的质疑）

留三样，随时能拿得出来：

1. **15 份例会记录**（D1–D15，`docs/例会记录/`）
2. **15 天燃尽图数据**（CSV 每日一行，日期连续）
3. **15 组截屏/照片** + 对应签入记录

> 一句话自证：**「打开仓库，例会记录按日期连号、燃尽图逐日有数、签入记录能与 Issue 对上。」**
