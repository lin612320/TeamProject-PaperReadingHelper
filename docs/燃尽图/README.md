# 燃尽图操作手册

> 用途：满足 Alpha 阶段 Scrum Meeting 博客的强制项（需求分析 PPT 第 3 页第 ②条）。
> 负责人：**P7**（每日记录）· 审核：**P1** · 数据来源：`docs/Alpha_Issue清单.md`

---

## 一、三个口径先说清（选错就白画）

| 口径 | 单位 | 优点 | 缺点 | 本项目是否采用 |
|---|---|---|---|---|
| **剩余 Issue 数** | 条 | 与 Issue 板一一对应，可核对、无法造假 | 不反映任务大小差异 | ✅ **主口径** |
| 故事点 | 点 | 反映工作量 | 7 人估点不一致，容易扯皮 | ⚠️ 可选补充 |
| 工时 | 小时 | 细 | 记录成本高，2.5 周来不及 | ❌ 不用 |

**决定**：Alpha 用「**剩余 Issue 数**」一条线，总数 **28 条**（来自 Issue 清单）。

---

## 二、谁的活、什么时候记

| 时点 | 动作 | 责任人 |
|---|---|---|
| D1 例会 | 建立表格，剩余数填 28 | P7 |
| **每日例会后 5 分钟** | 填写当日「实际剩余 Issue」 | P7 |
| 每完成一条 Issue | 状态改为已完成，从剩余数里减 | 对应负责人 |
| 第 6 周 / 第 7 周博客发布前 | 按区间各出一张图 | P7 |

**铁律**：**当日填当日**。事后补画的曲线必然平滑漂亮，一眼假；老师看的就是「有没有不下降的日子、为什么」。

---

## 三、怎么画（Excel / WPS，5 步）

1. 打开 `燃尽图模板.csv`（已含 D0–D15 与理想剩余数）
2. 每天例会后填 **实际剩余Issue** 一列
3. 选中 `工作日`、`理想剩余Issue`、`实际剩余Issue` 三列
4. 插入 → **折线图**（不要柱状图）
5. 收尾：
   - 横轴改成「日期」，纵轴标题「剩余 Issue 数」
   - 理想线设为**灰色虚线**，实际线设为**蓝色实线**
   - 图标题：`Alpha 冲刺燃尽图（D0–D15）`
   - 截图存为 `docs/燃尽图/燃尽图-第6周.png` / `燃尽图-第7周.png`

> 用飞书/腾讯在线表格也可以，好处是 P7 记录、P1 随时能看，链接放群里。

## 五、博客里必须配的三句话

只贴图不给解释是大忌。图下至少写清：

1. **本区间完成了哪些 Issue**：「D1–D8 完成 #1 #2 #3 #5 #9 #13 #17 等 12 条」
2. **曲线为什么没按理想线走**：「D4–D5 实际剩余持平，因 PDF.js 渲染环境问题阻塞两天，已由 P2 与 P1 结对解决」
3. **区间末结论**：「截至 D8 剩余 15 条，进度落后 2 条，方案是把 #20 抽样评估后移到 D13」

## 六、五个常见错误（直接判卷扣分点）

| ❌ 错误 | 后果 |
|---|---|
| 最后一天一次性补齐整条曲线 | 曲线过度平滑，一眼看出造假 |
| 只有一个点或一条水平线 | 等于没画 |
| 中途偷偷把总数改小让曲线「下降」 | 与 Issue 清单总数对不上，评审可直接核对 |
| 只放图不说话 | 看不出团队在管理进度 |
| 理想线画成实际线（两条线重合） | 说明没有真实记录 |
