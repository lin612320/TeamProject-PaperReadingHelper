> **今天数字没动（仍 45），但原因和昨天不一样，得单独说清楚。**
>
> **一、确实有干货进来。** 今天合了 `#74`（papers 六处查询与上传插入改用 `currentUserId()`）与 `#75`（qa、import 同样改造）。`papers.arxiv_id` 无唯一约束，加 user 维度不会冲突；存量 12 篇在 `user_id=1` 名下，`AUTH_ENFORCE=false` 期间前端行为不变，**无回归**。这部分是合格的。
>
> **二、但 `#75` 按验收不能关。** 它的验收写的是「qa + explain + import 三处过滤」，实际 **explain 一处完全没做**：`ExplainController` 全文没有 `JdbcTemplate`、也没有 `UserContext`（逐行核对，零命中），`paperId` 原样转发给 ai-service，而 ai-service 侧 `select title from papers where id = %s`、`select content from chunks where paper_id = %s` 两处都没有 user 维度。等于 A 用户传 B 的 `paperId`，划词解释就把 B 的标题和正文片段拿去当上下文了。契约 1.3.0 把划词解释明确列进 `authz` 六处，要求越权回 2001/404——这是 **S1 隔离漏洞**，已立 `BUG-024`。
>
> **三、顺带审出两条。** `BUG-025`：`ai-service:8000` 对外发布且 `/internal/*` 无鉴权，绕过 backend 全部校验直接读他人 chunk（Alpha 就有，本次改造让它从"调试方便"升级成"隔离旁路"）。`BUG-026`：`UserContext` 未设置时**静默回退 `1L`**，现在靠 `enforce=false` 兼容没事，一旦 `AUTH_ENFORCE` 打开，任何漏过 JwtFilter 的请求都会不报错地变成用户 1。
>
> **所以结论是**：`#74` 可以关；`#75` 把 explain 补上再关。今天曲线不掉这不亏——一条 S1 隔离漏洞挡在出口条件前面，比曲线好看重要。
>
> 另：`#71`（JwtFilter）仍挂着没关，代码早在 master 上；`#79` 同理，第 4 天了。今天站会按 README 第十节定责任人与截止时点，**下班前不关就记进例会记录**。

## 每天怎么更新（2 分钟）

```powershell
cd PaperMind

# 1. 记录今天剩余多少条（Beta 表）
.\scripts\burndown.ps1 -Csv docs\燃尽图\燃尽图-Beta模板.csv -Remaining 45 -Total 51

# 2. 重画图（三条参数：Beta 表 / Beta 图 / 关掉 scope 标记）
.\scripts\burndown-chart.ps1 -Csv docs\燃尽图\燃尽图-Beta模板.csv `
  -Out docs\燃尽图\燃尽图-Beta-当前.png `
  -Title "Beta 冲刺燃尽图（11-18 → 12-11 · 51 条）" -MarkLabel ""

# 3. 提交
git add docs/燃尽图 && git commit -m "chore: 更新燃尽图 (#3)" && git push
```

> Alpha 表（`燃尽图模板.csv`）保留不动，出历史图时用它；两轮日号各自从 0 起算（D / B）。
