## P1 林子航

### 一、学到的与改变的做法
1. **对模块细节的掌握要下沉**：本人对每个模块内部的细节没有十分了解，容易出现不理解与脱节。
2. **AI 的用法**：目前用 AI 做代码审查与记录整理。
3. **协作纪律**：个人开发前必须先拉取远端最新版本，开发后合并，否则会出现文件冲突。

### 二、发现的问题（流程层面）
1. **出口条件划分**：对团队工作量没有进行摸底与估计，导致确定出口口径时与实际日程对不上，多次动态调整。
2. **用户故事不清晰**：每一轮迭代前，都需要让每个成员明确该轮迭代的功能目标。
3. **issue 划分不合理**：存在多个具有依赖关系的 issue 和跨度大的 issue，导致燃尽图进展不均衡。
4. **组员参与度**：整体规划上组员参与度不高。
5. **环境差异**：不同环境下产品可能出 bug。

### 三、开放问题与建议
1. **动态调整 vs 团队积极性**：如果迭代周期的工作量由团队拟定，如何衡量工作量是否合适？如果团队提前完工，是动态调整顺延功能还是直接交付？若选前者，久而久之会存在团队积极性下降。
   → 朴素方案：在制定合理工作量的前提下，**将团队利益与产品收益挂钩**。
2. **并发提交的冲突隐患**：即便做到「先拉后合并」，同一时间段内多次提交仍难避免冲突。**尚无好办法，留作开放问题。**

## P3 杨绎平

### 一、学到的
1. **上传进度要用 XHR**，`fetch` 没有 progress 事件，想显示进度条必须回退到 `XMLHttpRequest`。
2. **nginx 不声明 MIME 类型会把 `.mjs` 返回成 `octet-stream`**，pdf.js 的 worker 直接被浏览器拒绝加载，PDF 整页白屏。**`include mime.types` 不够，`.mjs` 必须显式写 `application/javascript`**。

### 二、踩的坑
周日修改前的分支是旧版本 —— **开发之前一定要拉取最新代码到本地**。

## P4 刘万礼

### 一、学到的
1. **需求必须可度量、可验证**：错误码体系（1001/2001/3001/3003…）本质是出错处理需求。假 Key 返回 `400/2002` 这条需求把码写错了，直接导致实现和验收对不上。
2. **先契约再动手**：有契约时开工很快；没有契约时只能停下来确定后再开工。

### 二、踩的坑
11-03 晚第一次调 AI 服务解析接口，服务端返回 422 且 body 缺失，但我方日志里 JSON 明明是完整的 —— 一边说没收到、一边说发了，卡了近一小时。
最后写独立 Java 程序，用三种客户端打同一接口：默认配置 422、强制 HTTP/1.1 正常、`HttpURLConnection` 正常。
**根因：JDK `HttpClient` 默认尝试 HTTP/2 升级（h2c），uvicorn 不支持，请求体在升级协商里被丢掉了。**
→ 修法：显式 `.version(HttpClient.Version.HTTP_1_1)`，解析与问答两个调用统一。

## P5 吴啸天

### 一、学到的
1. **PyMuPDF `get_text("blocks")` 返回的是未旋转坐标**，旋转页必须先 `rect * page.rotation_matrix`，再按 `page.rect` 归一化；否则 90° 页的 y 能到 1.30，框直接画到页外。
2. **契约要先看再动手**：字段名、可空性、错误码没冻结就写代码，返工成本比想象高。

### 二、踩的坑
做 `#40` 时只按 `page.rect` 归一化，90° 旋转页的 y 到 1.30，框画到页外；后来改成先乘 `rotation_matrix`，并补了 90°/180°/270° 三组测试。

### 三、团队工作建议
1. **关 issue 前需要确认提交真的在仓库**，而不是只看 GitHub 状态。
2. **跨人依赖的 issue 要提前对齐**、订立契约，勿等到实现时才发现要补字段或接口没定。
3. **非必要不改契约**；必要时通过 PR 单独提交契约 commit 供 P1 审核。

## P6 刘征

### 一、学到的
1. **缓存 key 用「来源 + 关键词哈希」**，有缓存就直接用、不请求外部接口；外部接口挂了返回降级标识，保证断网时程序不卡死。
2. **配置一律写成 `${变量名:默认值}` 格式**，启动容器时通过 docker compose 传环境变量，没传就走默认值。

### 二、踩的坑
和 P4 同时改了同一个文件，`pull --rebase` 直接冲突。
→ **开发前一定要先拉最新代码；解冲突时要把双方改动都保留，不能图省事覆盖掉对方。**
