## E 类：环境清单（按角色装，不是人人都要装 Docker）

### 先说 Docker 是什么

**一句话**：把「软件 + 它需要的运行环境」打包成一个盒子，拿到任何电脑上一条命令就能跑起来。

类比：宿舍四个人要玩同一个游戏。传统做法是每人自己下载、自己装运行库、自己调设置，装一晚上还各不相同；Docker 的做法是把装好的整套东西打包，谁拿到都是一样的、开箱即用。

**Docker Compose** 再往上一层：一份 YAML 里写清「数据库、缓存、后端、AI 服务」这几个盒子，然后 `docker compose up` 一条命令全起来。

### 我们项目为什么用它

我们要的数据库是 **PostgreSQL + pgvector 扩展**（存论文信息和向量）。

| 不用 Docker | 用 Docker |
|---|---|
| 每人下载安装 PostgreSQL、再装 pgvector、改配置 | 一条 `docker compose up -d` |
| 你装 14 版、他装 16 版，报错对不上 | 镜像版本固定，人人一致 |
| 装错一次重装，一小时没了 | 删掉重来 10 秒 |

配置已写在仓库根目录 `docker-compose.yml`（postgres + redis），现在的状态是：**能起依赖，但还没人验证过**。

### 数据库那三条命令（P6 跑通后全组照抄）

```powershell
cd PaperMind
docker compose up -d          # 起 postgres + redis
docker compose ps            # 两个服务都要是 healthy
docker compose logs -f postgres   # 看日志，Ctrl+C 退出
```

改过 `docs/03-数据库表结构.sql` 之后要重建才会生效：

```powershell
docker compose down -v       # ⚠️ 会删掉数据库里所有数据
docker compose up -d
```

**`down -v` 会清空数据，别乱跑。**

### 注意：现在 `up` 起的是「依赖」，不是「整个项目」

整个项目要跑起来还差三个服务的代码：前端（Vue）、后端（Spring Boot）、AI 服务（FastAPI）。**仓库里现在还没有一行业务代码。**

所以 F4「一条命令起全栈」这个验收，**目前只到「依赖能起」这一步**，要等三个服务都有 Dockerfile 才算真达成。

### 常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| Docker 装完启动报「需要开启虚拟化」 | BIOS 里 VT-x / SVM 没开 | 进 BIOS 打开虚拟化，或用 WSL2 后端 |
| `java -version` 显示 1.8 | 系统里装了旧 JDK | 装 JDK 17 并设 `JAVA_HOME` |
| `python` 打不开 | Windows 应用商店的假 python | 装官方 Python 3.11，勾选 Add to PATH |
| `docker compose` 提示命令不存在 | 装的是老版 docker-compose | 用 Docker Desktop 自带的 `docker compose`（有空格，不是连字符） |
| 端口 5432 被占用 | 本机已装过 PostgreSQL | 停掉本地服务，或改 compose 里的端口映射 |
