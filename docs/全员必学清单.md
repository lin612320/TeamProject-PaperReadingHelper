# 论文阅读助手 · 全员必学清单

> 团队：七仙过海 · 适用：Alpha 迭代启动前（D1–D3）
> **总预算：全组每人 ≤ 4 小时**。Alpha 只有 2.5 周，学习不能挤占开发。
> 原则：**共同语言必须人人会；别人模块的原理只要能听懂；实现细节各自负责。**

---

## A 类：全员必学（D1–D3 完成，合计 ≤ 4h）

| # | 学什么 | 到什么程度（验收） | 时长 |
|---|---|---|---|
| A1 | **Git 协作流**：clone / branch / commit / PR / review / merge / 解冲突 | 能独立建 `feature/xxx` 分支、提 PR、被 review 后改完自己 merge | 60min |
| A2 | **Docker Compose 三个命令**：`up -d` / `logs -f` / `down` | 能一条命令起全栈，能看日志定位是哪个服务挂了 | 20min |
| A3 | **Issue 驱动 + 燃尽图** | 会从 Issue 板领任务、改状态、写进展；知道自己的 commit 要带 `#编号` | 20min |
| A4 | **接口契约与联调**：读 `api-contract.yaml`、Postman/Apifox 调接口、mock | 能在后端未完成时用 mock 把前端跑起来 | 40min |
| A5 | **HTTP / JSON / REST 常识**：方法、状态码、统一返回结构 | 能看懂一次请求失败是 4xx 还是 5xx，能说清错在哪一层 | 30min |
| A6 | **需求的可测试性**（需求分析 PPT 第 43 页） | 会区分 ✅「抽 10 题 ≥7 题正确」和 ❌「界面友好」 | 20min |
| A7 | **论文与合规常识**：双栏排版、PDF 页码与坐标、OA vs 付费墙、arXiv / DOI / OpenAlex、API 限流与 ToS | 能解释「为什么不能抓 IEEE 全文」「为什么引用要高亮页码」 | 30min |
| A8 | **统一约定**：日志打点、异常不裸抛、返回结构化错误 | 自己写的接口出错时返回 `{code, message, data}` 而不是抛堆栈 | 20min |

### A7 的合规红线（必须背下来）

- ⛔ 只抓**开放获取（OA）**全文，非 OA 只给原文链接
- ⛔ 不绕过付费墙、不做代理池/爬虫对抗
- ⛔ 遵守各 API 的限流与 Terms，做缓存与退避重试
- ❌ 知网、万方无公开 API；IEEE Xplore / Web of Science / Scopus 需机构订阅——**一律不接**

## B 类：全员要「听懂」，不要求会写（迭代中补，合计 ≤ 1.5h）

| # | 概念 | 到什么程度 |
|---|---|---|
| B1 | **RAG 五步**：解析 → 切片 → Embedding → 向量检索 → 拼 Context 生成 | 能用一句话向非技术同学解释我们的问答是怎么做的 |
| B2 | chunk、embedding、向量相似度、prompt、token 与成本 | 知道「为什么长论文要切片」「为什么 token 就是钱」 |
| B3 | PDF.js 文本层与坐标的关系 | 知道 bbox 为什么要归一化成相对页面宽高的比例 |
| B4 | 双栏解析难在哪 | 知道单栏「按顺序读」在双栏下会串行，Beta 才专门解决 |

## C 类：按角色选修（只学自己那块）

| 角色 | 必修内容 |
|---|---|
| **P2 前端 PDF** | PDF.js API（`getViewport` / `render` / `getTextContent` / `scrollPageIntoView`）、Canvas 渲染、坐标系换算 |
| **P3 前端页面** | Vue3 `<script setup>`、Element Plus 常用组件、Axios 拦截器、ECharts 基础 |
| **P4 后端业务** | Spring Boot 分层（Controller/Service/Mapper）、文件上传 multipart、RestTemplate/WebClient 调用 FastAPI |
| **P5 AI/RAG** | PyMuPDF `get_text("blocks", sort=True)`、sentence-transformers / bge 向量化、pgvector SQL、OpenAI SDK 兼容接口 |
| **P6 数据部署** | PostgreSQL + pgvector 扩展与索引（ivfflat / hnsw）、Redis 常用命令、Docker 资源与端口映射 |
| **P7 测试文档** | 等价类与边界值用例设计、Postman 集合、Markdown 博客排版、`git log --author` 统计签入 |

---

## D 类：明确**不用学**（避免浪费组员时间）

- Kubernetes、服务注册中心、消息队列（Kafka/RabbitMQ）——架构已砍
- Milvus / Neo4j / MinIO——已收敛为 pgvector + 本地存储
- 模型训练、微调、推理部署——不属于本项目客户端侧
- 爬虫对抗、代理池、验证码破解——合规不允许
- 复杂 CI/CD 流水线——Beta 再用，Alpha 手动起服务即可

---

## 验收方式（D3 前每人必须过，P1 抽查）

✅ 正确完成后：`git clone` → 建 feature 分支 → 改一行 README → 提 PR → 在 Postman 里调通**任意一个**已有接口 → 截图发群
❌ 只看完视频却说「我不会提 PR」= 没学会，D4 不能开工

## 群发精简版（可直接粘贴）

> 【Alpha 启动前必学 · 每人 ≤4 小时，D3 前完成】
> **必须会（4h）**：① Git 分支+PR+review ② `docker compose up/logs/down` ③ Issue 驱动开发与燃尽图 ④ 读接口契约、用 Postman mock 联调 ⑤ HTTP/JSON/状态码常识 ⑥ 什么叫「可测试的需求」 ⑦ 论文双栏/页码/OA 与合规红线 ⑧ 统一返回结构与日志规范
> **必须听懂（1.5h）**：RAG 五步、chunk/embedding/token 成本、PDF 坐标为什么要归一化、双栏解析难在哪
> **不用学**：K8s、消息队列、Milvus、模型训练、爬虫对抗
> **D3 验收**：clone → 建分支 → 改一行 → 提 PR → Postman 调通一个接口 → 截图发群。不会提 PR 的 D4 不能开工。
> **红线**：只抓开放获取全文，非 OA 只给链接；不碰付费墙；遵守 API 限流。
