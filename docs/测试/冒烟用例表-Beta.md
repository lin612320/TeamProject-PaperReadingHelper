## 层次

- **L1 主链冒烟**：用户必经路径（登录 → 上传 → 阅读 → 提问 → 引用跳转）
- **L2 功能验收**：单功能行为，浏览器+肉眼判定
- **L3 接口异常**：参数 / 错误码 / 边界，用 `curl` + 数据库对账

## 约定

- **S0** 不过 → Beta 不算完成（S0 = **主链断 / 演示走不通 / 出口必达项不达标**，出口必达项指双栏阅读流、登录与多用户隔离、非 OA 合规）；**S1** 不过 → 记问题、报告里说明；**S2** 记录即可。
- 状态只有五种：**未执行 / 通过 / 不通过 / 测不了 / 不适用**。
- **起草版豁免**：本版（v1.1），首版 v1.0 已于 11-22 入库；**W2 起**严格执行「未执行必须写原因」。
- **禁止 `docker compose down -v`**：`-v` 会删除 `hf-cache`（约 4.3 GB 向量模型）与 `pgdata`。本表涉及卷的用例（**B05-03、B17-01/02**）执行前后各 `docker volume ls` 截图留证。
- **不改代码**：P7 只提 Issue，发现缺陷挂 `docs/测试/BugList.md`，不顺手改代码（`团队分工明细.md` §四 红线）。
- **证据位置**：每条执行后截图/命令输出存 `docs/beta/测试/证据/<编号>-<日期>.png`（或 `.txt`），W4 写报告时直接引用。

## 判定口径（沿用 Alpha 三条硬规矩 + Beta 追加三条）

1. **「未执行」必须写原因**，格式：`未执行 —— 依赖 #75 未交付`。空白格一律打回（本版起草期豁免，W2 起执行）。
2. **「不通过」必须带 Bug 编号**（登记进 `docs/测试/BugList.md`），不许只写"不通过"。
3. **S0 必须全绿**；S1 红了记结论；S2 允许只做记录。
4. **越权类一律按「资源不存在」判**：返回 `2001 + HTTP 404`，**响应里连他人标题都不许出现**；出现 403 或回显标题即判不通过（契约 `x-conventions.authz`）。
5. **容器环境优先**：结论以 8081（nginx 容器）为准，5173 开发服务器仅作参考（Alpha BUG-013 只在容器里复现）。
6. **单条耗时断言不算压测**：B02-03（首屏 ≤3s）、B18-01（超时预算）验的是**单用户单次响应**，与 RC 的压测/并发无关。
7. **`bboxMode` 按精度判**（契约 1.3.1）：`precise` = 不跨栏且覆盖目标段落；`block` = 跨栏或整段并集；`null` = 无坐标。**与单栏/双栏无关**，不得按版面类型一刀切（BUG-023）。
